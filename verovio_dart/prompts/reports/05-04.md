## Desvios do C++ introduzidos

1. **`<defs>` via `parseMeiXml` + `MeiXmlNode.copy()`** — o C++ reutiliza um
   `pugi::xml_document sourceDoc` e faz `load_string` do XML de cada glifo,
   setando `@id` no nó fonte antes do `append_copy`. O port parseia cada
   glifo com `parseMeiXml` e seta `@id` **na cópia** (equivalente: o nó fonte
   é descartado a cada iteração). Nós não-elemento recebem cópia sem `@id`,
   como no C++ (`child.attribute("id")` é nó nulo fora de elementos).
2. **xpath → caminhada de pais** — `m_currentNode.select_node("ancestor::*[@font-family][1]")`
   vira um laço por `MeiXmlNode.parent` procurando o ancestral mais próximo
   com `@font-family` (o eixo `ancestor` é reverso; `[1]` é o mais próximo).
   Documentado no doc comment de `drawText`.
3. **Iteração por `runes`** — `DrawMusicText` recebe `std::u32string` (code
   points) no C++; a assinatura Dart carrega `String` (UTF-16) e itera
   `String.runes` (code points), o mesmo mapeamento dos demais device
   contexts. `setSmuflGlyph` não é usado pelo corpo SVG no C++ e aqui também
   não (paridade de interface mantida).
4. **`wtext` ignorado** — o corpo de `DrawText` no C++ só escreve `text`
   (UTF-8); o parâmetro `wtext` (UTF-32) não é usado. A assinatura Dart o
   mantém e o corpo o ignora, como lá. Documentado no doc comment.
5. **`VrvTextFont()`/`VrvTextFontFallback()`** — setters privados no C++; no
   port os campos `vrvTextFont`/`vrvTextFontFallback` já eram públicos
   (estilo da 05-02) e `drawText` apenas os atribui.

## Achados fora de escopo

1. **O critério `grep -c "UnimplementedError" = 0` é inalcançável sem tocar
   fora do escopo.** Restam **2** ocorrências, ambas de
   `appendAdditionalAttributes` — o `throw UnimplementedError` do
   `TODO(06-08)` (a maquinaria `Object::GetAttributes`/`AttModule::Get*` é
   da Fase 6/7) e a menção a ele no doc comment da biblioteca. Esse estado é
   pré-existente e estava documentado desde a 05-02 (o relatório da 05-03
   já o contabilizava). Nenhum método da superfície 05-04 lança erro.
   Reescrever o doc comment só para baixar o grep para 1, ou remover o
   throw, seriam cosmética/behavior change sem lastro no C++ — mantido como
   está e registrado aqui.
2. **A armadilha do prompt sobre `outputSmuflXmlEntities` não se aplica ao
   `SvgDeviceContext`.** A opção só é lida no export MEI
   (`iomei.cpp:324` e `:3226`), como flag pugixml `format_no_escapes`. O
   `Commit` do SVG usa sempre `pugi::format_default | format_no_declaration`
   (svgdevicecontext.cpp:224) e `RenderToSVG` (toolkit.cpp:1727) não passa
   nenhuma opção de escaping — não existe segundo caminho de codificação de
   SMuFL dentro do device context. O caminho default (caracteres SMuFL
   crus, controle `< 0x20` como `&#NN;`) já é o que `_textOutput`
   implementa desde a 05-02. Nada a portar; registrado para a 06-x, quando
   o export MEI for portado.
3. **Id do `pgFoot`/`fig`/`svg` do golden** — o pgFoot do golden (footer.svg
   via `DrawSvgShape`) ficou fora do documento mínimo do teste (não exerce
   nenhuma superfície 05-04: nem `<use>`, nem texto); a sequência de
   chamadas dele é responsabilidade da 05-06/05-08 (`view_page.cpp`).
