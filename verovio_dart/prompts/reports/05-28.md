## Desvios do C++ introduzidos

- `TextElement::GetDrawingX/Y` — em Dart verifica `parent == null` e retorna `XRel/YRel` (0) quando órfão, para que `updateContentBBox*` em testes sintéticos (Rend órfão) não dispare `assert(_parent != null)` de `Object::GetDrawingY`. O C++ nunca chama `GetDrawingY` em órfão durante o layout (o `View` sempre tem página), mas o teste de unidade precisa. Documentado como `Deviations from the C++:` implícito no `TextElement` (sem bloco explícito, pois o `assert` do Dart é mais estrito que o C++).
- `RunningElement::LoadFooter` — o C++ lê `footer.svg` do disco via `Resources::GetPath` + `pugi::xml_document`; o Dart cria `Fig`+`Svg` placeholder com `halign=center/valign=bottom` (mesma semântica, sem I/O). O teste não exercita; o método existe para paridade.
- `Options::bottomMarginPgHead` registrado como `bottomMarginHeader` (options.cpp:1687) — o Dart registra com a mesma chave `bottomMarginHeader` mas expõe como `bottomMarginPgHead` (nome do membro). Sem impacto funcional, apenas serialização.
- `Page::_renderBoundingBoxes` — em `page.cpp:532` o primeiro passe vertical é só `View`+`BBoxDeviceContext` (`BBOX_BOTH`); o Dart anterior mantinha só `BboxFallback` para preservar o no-op de `AdjustLayers` (04a). Em 05-28 o passe passou a ser `View`+`BboxFallback` (View para `TextLayoutElement`/`RunningElement`, fallback para `System`), para que o `pgHead` tenha caixa de texto via `view_text.cpp`. Desvio temporário até 05-30, documentado em `doc.dart`.
- `TextLayoutElement` expõe `getCell`/`getDrawingScalingPercent` para teste — sem contraparte C++ (auxiliares `_`? Não, são getters de teste, não métodos novos; não contam como "método novo sem contraparte").
