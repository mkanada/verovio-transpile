### Normalização do sufixo aleatório de id

Os goldens foram gerados sem `-x` (`tool/golden.sh`), então **todo** id gerado depende da semente
aleatória daquele run (`Object::SeedID`/`Object::GenerateHashID` em `object.cpp`). Normalização por
documento, na ordem de primeira aparição (passe prévio em ordem de documento: atributos `id`, depois
refs `xlink:href`, depois tokens `id-...` de `class`):

- id do documento (root `<svg id>`, ex. `o3u8kcw`) → `@doc`;
- ids de glifo `<código>-<docId>` (ex. `E050-o3u8kcw`) → `E050-@doc` (mantém o código do glifo);
- demais ids de objeto (ex. `c1d4rhaq`) → placeholders posicionais `@id1`, `@id2`, ... — dois
  documentos estruturalmente idênticos normalizam para árvores idênticas, independente da semente;
- tokens de `class` que carregam ids também normalizam: o `id-<gId>` composto de
  `SvgDeviceContext::AppendIdAndClass` para gráficos SPANNING/SYMBOL_REF (ex.
  `slur id-j1phddu5 spanning`) e o id de marcos de fim (ex. `pageMilestoneEnd pqb7fiy`, onde
  `View::DrawPageElement` passa o id do elemento inicial como classe);
- texto: `#<docId>` no CSS de `<style>` → `#@doc` (o CSS default leva prefixo `#o3u8kcw`).

Justificativa da escolha (o prompt pedia decisão): normalizar por placeholder posicional, não fixar
a semente. Fixar a semente só seria necessário para igualdade byte a byte no fim da fase (05-25);
para o modo estrutural do harness, placeholders posicionais são robustos e não exigem portar o
gerador de ids.

## Desvios do C++ introduzidos

Nenhum — a tarefa não porta código C++. Notas de escopo da própria harness (documentadas no
cabeçalho de `svg_compare.dart`):

- O modo estrutural compara só `class`, `id`, `xlink:href`, árvore, `<defs>` e texto de folhas;
  outros atributos (`style`, `fill`, `type`, ...) ficam fora do escopo do 05-00 e podem ser
  acrescentados pelas tarefas seguintes, se necessário.
- O modo numérico usa a lista fechada de atributos do prompt (`kNumericAttributes`).
- Texto intercalado entre elementos filhos (mixed content) não é comparado — só o de
  elementos-folha.

## Achados fora de escopo

- O número real de categorias do corpus é **75**, não 69 como estimava o prompt (contagem dinâmica
  de diretórios sob `test/corpus/`; o relatório imprime o número real).
- Com a skip-list obrigatória dos 2 arquivos não-UTF-8, o teto desta fase é **621/623** limpos, não
  623 — os goldens `dir-011.svg`/`dir-012.svg` existem, mas o leitor Dart rejeita os MEI. A linha
  de resumo mantém o denominador 623 exigido pelo prompt; as tarefas seguintes devem esperar o
  teto 621.
- `--mode=numeric` mantém o veredito numérico honesto: divergência de forma (nomes/contagem de
  filhos) também aparece no modo numérico com desvio 0, para "numérico limpo" implicar forma
  comparável. Decisão de desenho documentada no código, não um desvio do C++.
