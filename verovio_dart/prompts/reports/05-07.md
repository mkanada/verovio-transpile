## O que foi feito

  `view.dart` (decisão de particionamento da 05-06). As 21 funções do
  arquivo — linhas (verticais/horizontal/oblíqua, simples e segmentadas),
  retângulos (vazio/preenchido/arredondado), elipse, polígono oblíquo,

  comment de `view.dart` e de `view_graph.dart`): Dart não consegue
  dividir o **corpo** de uma classe entre arquivos — o `part` compartilha a
  library (e portanto a privacidade: `_currentOffsets`, `_Offset`, e os
  campos de `View`), mas os métodos do `view_graph.cpp` precisam de um
  declarador próprio. Eles vivem numa **`extension ViewGraph on View`
  declarada dentro do `part`**: mesma library (privados acessíveis, como a
  visibilidade de membro do C++ em todos os `view_*.cpp`) e despacho
  estático, equivalente aqui porque `vrv::View` não tem métodos virtuais de
  desenho e não é subclassada. Os `view_*.cpp` seguintes seguem o mesmo
  padrão (`ViewPage`, `ViewElement`, …).

## Divergências em aberto

Nenhuma nova na aritmética portada. Uma dependência indireta continua com o
desvio já documentado em `doc.dart` (ver "Achados fora de escopo" 1): o
`count` de `DrawSmuflLine` replica a fórmula do C++ exatamente, mas os

## Desvios do C++ introduzidos

1. **`extension ViewGraph on View` dentro do `part`** — o C++ continua a
   classe `View` em `view_graph.cpp`; Dart não divide corpo de classe entre
   arquivos. A extension é declarada no `part` da library `view.dart`
   (decisão da 05-06 preservada): privados da library acessíveis e despacho
   estático, equivalente porque `View` não tem métodos virtuais de desenho.
   Registrado no doc comment dos dois arquivos.
2. **`DrawSmuflCodeWithCustomFont` portada como código vivo**: no C++ a
   função está comentada (view_graph.cpp:259-277). O corpo está completo na
   fonte original e a tabela de funções do prompt a lista — o port mantém
   o comportamento do corpo (swap de `Resources::SetCurrentFont` sem
   `allowLoading`, restore no fim), documentado no doc comment.
3. **Métodos "privados" do C++ ficam públicos** (padrão do port, como na
   05-06): todas as `Draw*` de `view_graph.cpp` são privadas em `view.h`;
   extension members são a API pública do Dart aqui.
4. **`DeviceContext *dc` → referência não-nulável** (`assert(dc)`
   subsumido); `char32_t code` → `int` (code point); `std::u32string` →
   `String` UTF-16 (os code points SMuFL usados são BMP — um code unit por
   glifo; `String.fromCharCode`/`String.fromCharCodes` preservam os pontos).
5. **`GetDrawingSmuflFont` devolve a mesma instância** (`m_drawingSmuflFont`
   por referência no C++): o campo `drawingSmuflFont` é `final` no Doc e
   cada chamada só atualiza faceName/pointSize — o aliasing é o mesmo.
6. **`Svg::GetWidth/GetHeight` re-parsam o conteúdo**: o C++ lê o atributo
   do nó pugixml armazenado; o Dart armazena a string serializada
   (decisão da fase de leitura) e re-parseia com `parseMeiXml` em cada
   chamada (o mesmo que `DrawSvgShape` já faz). O `atoi` da libc virou o
   helper privado `_atoi` com a mesma semântica.
7. **`Svg::Get()` → `svg.content ?? ''`**: `Get()` devolve o nó pugixml
   (possivelmente vazio); `DeviceContext.drawSvgShape` no port recebe a
   string e re-parseia — desvio já documentado na 05-04.
8. **Defaults de parâmetro**: os defaults declarados em `view.h` viram
   parâmetros opcionais posicionais nas assinaturas Dart (`[int dashLength
   = 0, int gapLength = 0]`, `[bool setBBGlyph = false]`,
   `[PenStyle penStyle = PenStyle.solid]`, `[int start = 0, int end = 0]`,
   `[int staffSize = 100, bool dimin = false, bool setBBGlyph = false]`,
   `[HorizontalAlignment alignment = HorizontalAlignment.left]`).
9. **`TextDrawingParams`** portada integral (14 campos, incluindo os que
   esta tarefa ainda não usa — `m_laidOut`, `m_enclosedRend`, etc.) para
   `text_elements.dart` (o espelho de `textelement.h`); o `m_` prefix cai
   (convenção do repositório) e o destrutor virtual não tem equivalente.

## Achados fora de escopo

1. **`Doc.getGlyphWidth`/`getGlyphAdvX` ainda são as aproximações da fase
   headless** (doc.dart:2108-2159, "Deviation: the SMuFL glyph metrics
   arrive with the resources phase"): o C++ real (doc.cpp:1872-1895)
   consulta `GetResources().GetGlyph(code)` e multiplica
   `* m_drawingSmuflFontSize / unitsPerEm` com truncagem inteira. Impacto
   direto nesta tarefa: o `count` de `DrawSmuflLine` usa a aproximação
   (ex.: glifo fora da tabela → 1.75 staff spaces genéricos), então a
   quantidade de glifos de extensor pode divergir do C++ nos goldens.
   Substituir os dois getters pela versão resources-based é fiel ao C++, mas
   muda o comportamento de layout da Fase 4 (larguras de ligaduras, spacing
   de grace notes) — não feito aqui por ser refactor fora da fatia.
   **Urgente antes da 05-08/05-09** (primeiro compare_svg que conta).
2. **`SymbolDef.getSymbolSize` sem testes dedicados de modelo**: exercitado
   indiretamente pelos testes de `DrawSymbolDef`; a paridade com
   symboldef.cpp:66-100 (incluindo o `dimin` truncado) foi conferida a olho,
   não por fixture.
3. **O prompt pede "um teste por primitiva" ≥ 403 total** — a suíte ficou
   com 35 testes novos (2 primitivas têm testes extras para os ramos
   `dimin`/`fill`/dash; `drawFilledRectangle` é delegação e tem um teste
   próprio). Total geral: 586.
