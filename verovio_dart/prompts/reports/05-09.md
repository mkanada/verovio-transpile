## Divergências em aberto

1. **Offset vertical constante em `score-001`** (não introduzida por este
   código, mas encontrada testando-o): a linha inicial de sistema desenhada
   por `DrawStaffGrp` (`M13 1083 L13 9315` no golden) sai como
   `M13 354 L13 8586` no Dart — mesmo x, mesmo comprimento de traço
   (8232 em ambos), mas deslocada uniformemente por 729 unidades lógicas.
   Isolei a causa até `Staff.getDrawingY()` de `staffDef n=1` (28346) e
   `n=6` (20834) no Dart: a matemática de `drawStaffGrp`
   (`yTop = first.getDrawingY(); yBottom = last.getDrawingY() - ...`)
   reproduz esses valores exatamente — não há bug na fórmula portada nesta
   tarefa. `system.getDrawingY()` bate com `doc.drawingPageContentHeight`
   (28700) em ambos, o que sugere que o sistema está posicionado
   verticalmente sem a margem/offset que o C++ aplica. Hipótese nomeada:
   `headless_extents.dart` (o substituto temporário do `View` usado pela
   Fase 4 para preencher bounding boxes, marcado para deleção na tarefa
   05-11, ver `CLAUDE.md`/`00-MESTRE.md` seção 2) aproxima alguma altura
   usada no `AlignVerticallyFunctor`/cast-off de forma que o sistema acaba
   ~729 unidades mais alto do que o C++ real. Como o teste desta tarefa usa
   comparação estrutural (sem coordenadas — mesmo modo de
   `tool/compare_svg.dart`), essa divergência não bloqueia a 05-09, mas
   deve ser reexaminada quando a 05-11/05-12 trocarem `headless_extents.dart`
   pelo `View` de verdade.
2. **`score-002` não quebra em dois sistemas no Dart** (o golden C++ tem
   dois): rodar `doc.prepareData()+layOut()` sobre `score-002.mei` emite

## Desvios do C++ introduzidos

- `drawScoreDef`'s `barLine` parameter: `BarLine?` no lugar do ponteiro
  `BarLine * = NULL` (nulabilidade Dart padrão do port).
- `drawGrpSym`: o parâmetro de saída `int &x` do C++ (`DrawGrpSym(..., int
  &x)`) virou valor de retorno (`int drawGrpSym(...)`), documentado no doc
  comment do método — mesmo padrão já estabelecido no arquivo para outras
  saídas por referência.
- `TextListInterface.getTextLines()`: o C++ (`object.cpp:1581`) só corta uma
  linha quando encontra `<lb>` **e** o buffer acumulado não está vazio;
  quando vazio, ele cai no `vrv_cast<Text*>(child)` do próprio `<lb>` — UB em
  C++, nunca de fato exercitado. O port do Dart pula o `<lb>` de buffer
  vazio em vez de tentar esse cast, que o sistema de tipos do Dart não deixa
  survivir. Documentado no doc comment do método.
- `DrawBrace`'s bezier branch: o array `Point points[4]` mutável do C++ (com
  `bez1[i] = points[i]` copiando por valor a cada passo) foi portado
  reproduzindo a mesma mutação sobre um `List<Point>` de fato mutável
  (`Point` já é mutável no port), com `bez1`/`bez2` recebendo `Point(...)`
  novos a cada atribuição para não aliasing — sem isso, a segunda curva
  sobrescreveria os pontos já usados pela primeira `drawCubicBezierPathFilled`.
