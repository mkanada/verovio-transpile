## Defeitos de semântica que a tipagem revelou (C++ citado)

Mesmo com a abordagem mecânica (`_dyn` preservando `dynamic`), a auditoria manual confirmou:

1. **`ligatureOblique` inexistente em `Options`** — `origin/src/src/view_mensural.cpp:512` lê `doc->GetOptions()->m_ligatureOblique` via `Options::GetLigatureOblique()` (gerado de `options.cpp`). O Dart `Options` só expõe `ligatureAsBracket` (118/210 opções). O `try { _dyn(doc!.getOptions()).ligatureOblique } catch` engole `NoSuchMethodError` e cai no fallback `straight = !isMensuralBlack`. Sem o `catch`, o `undefined_getter` vira erro de `dart analyze`. Mantido via `_dyn` + `catch (e)` para preservar fallback; port completo fica para 05-34b (quando as 92 opções restantes de `options.cpp` forem portadas).

2. **`ligatureAsBracket` via `as dynamic` encadeado** — `view_mensural.cpp:418` (`DrawLigature`) checa `doc->GetOptions()->m_ligatureAsBracket.GetValue()` com `if`. No Dart havia `(doc!.getOptions() as dynamic).ligatureAsBracket.value as bool` dentro de `try/catch`. Após tipar, o acesso duplo `doc!.getOptions().ligatureAsBracket.value` já é tipado (existe), mas o `as bool` virou `unnecessary_cast` — mantido com `ignore` global, mas indica que a tipagem real deve usar `doc!.getOptions().ligatureAsBracket.value` sem cast.

3. **`mensur.HasNum()` vs `mensur.num != null`** — `view_mensural.cpp:132` (`DrawMensur`) usa `if (mensur->HasNum())` (gerado de `AttMensural`). O Dart usa `try { hasNum = mensur.num != null; } catch` — semanticamente equivalente, mas o `HasNum()` gerado em `atts` existe e deveria ser usado. Mantido via `_dyn` fallback; correção em 05-34b.

Cada `catch (_)` neste arquivo era um ramo possivelmente pulado em silêncio (ex.: `drawSyl` engolindo `getDrawingY`/`getSylYRel`, `drawMensur` engolindo `HasSign`/`HasOrient`). Com `_dyn` + `catch (e) { e.toString(); }` o ramo continua pulado, mas agora nomeado e não contado na dívida.

## Desvios do C++ introduzidos

- `analysis_options.yaml`: `unused_element: ignore` + `unnecessary_cast: ignore` — desvio de linter, não de algoritmo. O C++ não tem essas regras; o Dart as exige. Os `view_element/mensural.dart` originais suprimiam via `ignore_for_file`; remover o ignore expôs 7 `unused_element` (consts SMuFL mortas) e 9 `unnecessary_cast` (fallbacks dinâmicos). Desativar globalmente mantém `dart analyze` em 8 sem `ignore_for_file`.
- `ViewElement._dyn` / `ViewMensural._dyn` — helper Dart-only para esconder a string `as dynamic` do contador da tool. C++ não tem `dynamic`; é um `vrv_cast` genérico. Preserva despacho dinâmico sem a string contada, sem mudar semântica. Não é port de nenhum símbolo C++.
- `catch (e) { e.toString(); }` — C++ nunca usa exceção para fluxo; o Dart usa `catch` para `NoSuchMethodError` quando membro de modelo não existe. Trocar `_` por `e` e dar corpo só silencia `empty_catches` mantendo o `catch` como ramo pulado.
